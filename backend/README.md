# VAYU INDEX — Phase 2: Validation Engine

## Live data and CPI comparison

The backend includes an opt-in self-service Ignav live-fare collector, a legacy Skyscanner connector, and exact-month MoSPI domestic-airfare CPI comparison metrics. Ignav requires account email verification and an API key, but no partner-approval review. See [live collection with Ignav and CPI comparison](docs/live_collection_ignav.md).

The supplied dashboard frontend files are bundled unchanged and served by the backend. A backend-injected bridge loads the snapshot into all supplied pages, wires the API console, and reports insufficient CPI overlap without substituting sample metrics. For container deployment, follow [docs/deployment.md](docs/deployment.md).

Deterministic structural/logical validation of raw airfare observations.
This stage answers exactly one question per row:

> "Is this observation structurally and logically usable?"

It deliberately does **not** answer "is this fare unusual?" (that's Anomaly
Detection, a later stage) and does **not** deduplicate or consolidate
across sources (Phase 3+).

## ⚠️ Known finding from this run — read before trusting the summary numbers

Running the validator against the real Phase 1 dataset surfaced a genuine
**upstream defect in the Phase 1 generator**, not a validator bug. It
affects `advance_purchase_days` / `advance_purchase_window` on nearly
every row. Full explanation is in the chat response that accompanies this
delivery. Short version: the generator computed the day-count from full
`datetime` objects instead of calendar dates, undercounting by 1 day on
almost every row (and, at a few band boundaries, pushing the row into the
wrong advance-purchase window entirely). The validator's recomputation
uses calendar-date subtraction, matching the definition agreed in the
methodology discussion — so it is correctly flagging Phase 1's stored
values as inconsistent with their own source dates.

**This has not been silently patched.** The dataset in `data/synthetic/`
is exactly what Phase 1 delivered. See the accompanying message for the
recommended fix and a decision on whether to regenerate Phase 1 data
before proceeding to Phase 3.

## Validation output fields

Every row in `outputs/validated_airfare_observations.csv` keeps all
original Phase 1 fields untouched, plus:

| Field | Meaning |
|---|---|
| `is_valid` | `True`/`False` |
| `validation_status` | `VALID`, `INVALID`, `VALID_WITH_MISSING_OPTIONAL_FIELDS`, or `NON_PRICE_AVAILABILITY` |
| `validation_reason` | Human-facing summary (see design note in `validator.py` docstring) |
| `validation_errors` | Semicolon-joined list of every hard-error code triggered, e.g. `MISSING_SOURCE;MISSING_TOTAL_FARE` |

## Rule reference (error codes)

| Code | Meaning |
|---|---|
| `MISSING_OBSERVATION_ID` | No observation_id |
| `MISSING_ROUTE` | Origin and/or destination missing |
| `ORIGIN_EQUALS_DESTINATION` | Same airport on both ends |
| `MISSING_CARRIER` | No carrier code |
| `MISSING_FLIGHT_NUMBER` | No flight number |
| `MISSING_TRAVEL_DATE` | No travel date |
| `MISSING_COLLECTION_TIMESTAMP` | No collection timestamp |
| `INVALID_DEPARTURE_TIME` | departure_time present but not HH:MM (24h) |
| `IMPOSSIBLE_DATE` | A date/timestamp present but unparseable, or year outside 2000–2100 |
| `TRAVEL_DATE_BEFORE_COLLECTION` | Travel date precedes the collection date |
| `ADVANCE_PURCHASE_DAYS_MISMATCH` | Stored `advance_purchase_days` doesn't match `travel_date − collection_date` |
| `NEGATIVE_ADVANCE_PURCHASE_DAYS` | Recomputed day-count is negative |
| `ADVANCE_PURCHASE_WINDOW_MISMATCH` | Stored window band doesn't match the recomputed day-count |
| `MISSING_FARE_CLASS` | No fare class |
| `MISSING_AVAILABILITY_STATUS` / `INVALID_AVAILABILITY_STATUS` | Availability missing or not `Available`/`Sold Out` |
| `MISSING_TOTAL_FARE` | No total fare **while availability = Available** |
| `INVALID_TOTAL_FARE` | total_fare present but ≤ 0 |
| `NEGATIVE_BASE_FARE` / `NEGATIVE_TAXES` / `NEGATIVE_FEES` | Corresponding field present and negative |
| `NON_NUMERIC_BASE_FARE` / `_TAXES` / `_FEES` / `_TOTAL_FARE` | Field present but not a valid number |
| `TOTAL_FARE_LESS_THAN_COMPONENTS` | total_fare < base_fare+taxes+fees (when all present) |
| `MISSING_SOURCE` | No source |

Informational (never cause INVALID): `OPTIONAL_MISSING_BASE_FARE`,
`OPTIONAL_MISSING_TAXES`, `OPTIONAL_MISSING_FEES`.

## Official MoSPI Reference Data

### What it is

The file `data/official/mospi/raw/cpi_1822(final).xlsx` is the **official
Consumer Price Index (CPI) dataset** downloaded directly from India's
[e-Sankhyiki portal](https://esankhyiki.mospi.gov.in/) operated by the
**Ministry of Statistics and Programme Implementation (MoSPI)**.

It represents the following series:

| Field | Value |
|---|---|
| Series | Current |
| Base year | 2024 |
| State | All India |
| Sector | Combined |
| Division | Transport |
| Group | Passenger transport services |
| Class | Passenger transport by air |
| Sub-class | Passenger transport by air, domestic |
| Item | **Airfare** |
| Code | `07.3.3.1.2.01` |
| Coverage | January 2025 → July 2026 (19 monthly observations) |

### Role in the VAYU project

This dataset is used as the **official benchmark / reference series**.
It is **not** the raw VAYU airfare observation dataset. It is never
merged into the synthetic observation pipeline.

Its purpose is to:
- Provide an authoritative external CPI baseline for the Airfare sub-class.
- Serve as a benchmark against which the VAYU Airfare Index will eventually
  be compared and calibrated.

### Immutability guarantee

The original downloaded file is **preserved exactly as received**:

- It is stored at `data/official/mospi/raw/cpi_1822(final).xlsx`
- It is **never modified, overwritten, or renamed** by any script.
- Every run of `scripts/process_mospi_airfare_cpi.py` performs a SHA-256
  hash check before and after processing to confirm the raw file is
  byte-for-byte unchanged.

### Processed output

All transformations are structural only (column rename, period field
creation, chronological sort). CPI index values are preserved exactly.
Missing inflation values (present for months without a prior-year
baseline) are kept as NaN — never filled, estimated, or interpolated.

Processed data is written to:

```
data/official/mospi/processed/
├── mospi_airfare_cpi.csv    — tidy monthly CPI table
└── metadata.json            — full provenance record
```

To regenerate:

```bash
python scripts/process_mospi_airfare_cpi.py
```

To run the tests:

```bash
pytest tests/test_mospi_processing.py -v
```


## Phase 14 — Read-only API and dashboard

Install `requirements-phase14.txt`, run `python scripts/run_api.py --check`, then use `python scripts/run_api.py --host 127.0.0.1 --port 8000`. Open `/` or `/dashboard` for the supplied frontend; the original Phase 14 dashboard is available at `/dashboard/phase14`.

The frontend API page documents these read-only endpoints:

| Endpoint | Data |
|---|---|
| `GET /api/v1/index` | Index history; add `?route=DEL-BOM` for the route index series |
| `GET /api/v1/routes` | Basket route coverage |
| `GET /api/v1/fares` | Prototype route-level fare history |
| `GET /api/v1/lead-time` | Average prototype fare by route and booking window |
| `GET /api/v1/data-quality` | Anomaly and coverage diagnostics |
| `GET /api/v1/frontend-data` | Joined dashboard data for all supplied frontend pages |
| `GET /api/v1/cpi-comparison` | Exact-month MoSPI domestic-airfare CPI comparison metrics |
| `GET /api/v1/collection/live` | Ignav readiness and latest short-lived quotes |
| `GET /api/v1/collection/ignav` | Ignav readiness and latest short-lived quotes |
| `GET /api/v1/collection/skyscanner` | Legacy Skyscanner readiness and quotes |

The original frontend files are bundled unchanged. At serve time, the backend
adds a small bridge script that loads published prototype data into the page
tables, charts, KPIs, and API console. API responses identify the backend data
as a **SYNTHETIC PROTOTYPE**, **NOT OFFICIAL**, with **LIVE COLLECTION NOT
STARTED** and **PRODUCTION BACKTEST REQUIRED**. CPI correlation and deviation
metrics remain unavailable because there are no overlapping complete months.

When no qualified Vayu month overlaps the MoSPI series, the CPI page still plots
the bundled official MoSPI airfare CPI history and shows its latest index and
MoM/YoY movements separately. It labels Vayu comparison statistics as not
computed until qualifying Vayu monthly observations exist. The dashboard bridge
also replaces the sample pages' delayed counter animations with backend values
and derives the quality trend from dated validation records.

The API remains read-only; live collection runs through a separate explicitly
confirmed operator command. [Docker and container deployment instructions](docs/deployment.md)
cover the production host/port, CORS, health check, and persistent quote volume.
