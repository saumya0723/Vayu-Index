# Phase 13 real airfare collection methodology

Status: the opt-in Ignav self-service fare API connector and a separate legacy Skyscanner Flights Live Prices connector are available; no real collection has started until an operator supplies credentials and confirms a bounded run. The locked Phase 5 basket SHA-256 is `dc57e6d470a2ed9061dd82a92c84943749c3c648cef00b85b3f250df2f87c181`. Both directions remain distinct under each undirected route ID. APWs are exact T+1/T+7/T+15/T+30/T+45 calendar dates and rounds are 09:00, 14:30, and 20:15 Asia/Kolkata. See [Ignav collection details](live_collection_ignav.md).

All eleven adapters ship `AUTHORIZATION_REQUIRED`; dry-run and fixture modes make no requests. Live fails closed unless documented authorization, approved terms reviewed within 30 days, unchanged terms hash, known contract limits, enabled adapter, health check, and schedule feasibility all pass. No CAPTCHA/bot bypass, evasion, private API reverse engineering, credential rotation, cookie harvesting, or fake accounts is allowed. Manual capture is diagnostic and separate.

Raw payloads, when future authorized collection exists, are immutable SHA-256 content-addressed artifacts. Attempts and observations are separate. Missing, sold-out, blocked, and failed attempts never become zero-price observations. Money uses Decimal; unsupported currency and unknown fare classes are ineligible for Phase 2 handoff. Legacy `fees` is a source aggregate or the sum of explicitly disclosed non-tax components only.

The first 19 canonical columns exactly match Phase 2. Phase 13 extensions preserve exact timestamp/timezone, raw labels, source identity, query/request/attempt IDs, artifact hash, versions, and handoff eligibility. Phase 6 retains deduplication ownership. Phase 7/8 still recognize legacy source/carrier registries; continuation of distinct real sources requires a separate versioned future update. Phase 2 binary numeric parsing is locked technical debt. Retention metadata is configurable; no deletion schedule is invented. Thirty-day readiness means machinery and gates can support 30 consecutive days, not that collection occurred.

The separate live connector is documented in [live_collection_skyscanner.md](live_collection_skyscanner.md). It records provider quotes to a diagnostic feed and does not blend them into the synthetic published Vayu index.
